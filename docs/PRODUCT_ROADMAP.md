# Racoon Typper — Product Roadmap (от простого к сложному)

Продуктовая дорожная карта. Идём от простых, низкорисковых улучшений к
сложным, требующим инфраструктуры. Каждый этап самодостаточен и проверяем.

**Версия:** 1.1.0 (опубликована)
**Ветка:** `master` (рабочая копия `/home/yago/Desktop/racoon-typper`)
**Обновлено:** 2026-08-10

---

## Принципы

- **От простого к сложному:** сначала то, что можно сделать и проверить за
  один заход, потом то, что требует инфраструктуры/интеграций.
- **Каждый этап = отдельный коммит/PR** с проверкой (`svelte-check`, тесты, CI).
- **Не ломать работающее:** изменения аддитивные, обратная совместимость.
- **Проверяемо:** у каждого этапа есть критерий готовности.

---

## Этап 1 — Гигиена репозитория (простое, срочное)

Незакоммиченные UI-правки (календарь, Vim-подсказка, кнопка «Заново»,
guard от повторного запуска) лежат в рабочей директории. Их нужно зафиксировать.

- [ ] Закоммитить текущие изменения фронтенда одним PR.
- [ ] Добавить в `.gitignore` посторонние файлы агентов: `.hermes/`, `.zcode/`, `rdmglm.md`.
- [ ] Проверить, что `git status` чист после коммита.
- [ ] Прогнать полный набор проверок (svelte-check, build, тесты, clippy).

**Критерий готовности:** `git status` чист, CI зелёный, изменения в `master`.

---

## Этап 2 — Тесты для новых UI-компонентов (простое)

Новые компоненты (календарь вкладов, подсказка Vim, кнопка «Заново») без тестов.

- [ ] Добавить unit-тесты для логики календаря (уровни интенсивности, построение грида).
- [ ] Добавить тесты для `restartTest` (прерывание + перезапуск).
- [ ] Проверить, что тесты гоняются в CI.

**Критерий готовности:** новые тесты зелёные, покрытие ключевой логики.

---

## Этап 3 — Улучшение календаря вкладов (простое)

Сейчас календарь показывает только число тестов в день.

- [ ] Переключатель метрики: тесты / время / уроки.
- [ ] Легенда с числами (как у GitHub: «меньше → больше» с диапазонами).
- [ ] Подсветка сегодняшнего дня.
- [ ] Локализация подписей месяцев (сейчас всегда английские).

**Критерий готовности:** календарь переключает метрики, подписи на языке UI.

---

## Этап 4 — Расширение Vim-режима (среднее)

Сейчас Vim — только навигация h/l/k/j по вкладкам.

- [ ] Режимы (normal/insert) с визуальным индикатором.
- [ ] `gg` / `G` — в начало/конец страницы.
- [ ] `/` — поиск по тексту теста.
- [ ] `r` — перезапуск теста (уже есть кнопка, добавить хоткей).
- [ ] Подсказка в настройках расширяется под новые клавиши.

**Критерий готовности:** Vim-режим покрывает навигацию + базовые команды, подсказка актуальна.

---

## Этап 5 — Автообновление (среднее, высокий UX-эффект)

Сейчас пользователь скачивает релиз вручную с GitHub Releases.

- [ ] Подключить `tauri-plugin-updater`.
- [ ] Настроить endpoint обновлений (GitHub Releases как источник).
- [ ] UI: уведомление о доступном обновлении + кнопка «Обновить».
- [ ] Проверить на Linux и Windows.

**Критерий готовности:** приложение находит и устанавливает новую версию.

---

## Этап 6 — Распространение (среднее/сложное)

Релиз только на GitHub Releases. Расширить охват.

- [ ] **Flathub** — Flatpak-манифест уже валидируется в пайплайне; довести до публикации.
- [ ] **AUR** — пакет для Arch (у владельца есть paru/yay).
- [ ] **winget** — публикация для Windows.

**Критерий готовности:** приложение доступно минимум в одном дополнительном канале.

---

## Этап 7 — Рефакторинг `App.svelte` (сложное)

`App.svelte` разросся (850+ строк). Разбить на feature-модули.

- [ ] Вынести состояние теста в отдельный store.
- [ ] Вынести навигацию/настройки в свои модули.
- [ ] Без изменения пользовательского поведения.

**Критерий готовности:** `App.svelte` заметно меньше, поведение не изменилось, тесты зелёные.

---

## Этап 8 — Продвинутые функции (сложное, по желанию)

- [ ] Многопользовательские рекорды / таблица лидеров (нужен бэкенд).
- [ ] Облачная синхронизация профиля между устройствами.
- [ ] Экспорт статистики в сторонние сервисы.

**Критерий готовности:** определяется на этапе планирования.
